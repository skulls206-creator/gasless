## ARCHITECTURE CONTEXT (read carefully before writing any code)

### Current TRON Wallet (do not break)
- Non-custodial: ed25519-equivalent keypair generated in the browser, encrypted locally, private key never sent to server
- Sponsor wallet covers fees via TRX top-up / energy delegation
- Tokens: USDT (TR7NHqjeKQxGTCi8q8ZY4pL8otSzgjLj6t) and USDC (TEkxiTehnzSmSe2XqrBj4w32RUN966rdz8)
- Uses TronWeb SDK

### New Solana Wallet (same non-custodial model)
- Keypair: ed25519 (use `@solana/web3.js` `Keypair` class)
- Generate keypair in the browser → encrypt private key locally (same encryption pattern used for TRON key) → user signs transactions client-side → server NEVER sees the private key
- Sponsor wallet (`feePayer`) covers ALL fees: base transaction fee (~0.0002 SOL) AND Associated Token Account (ATA) creation rent (~0.002 SOL / ~$0.30 per new recipient, first time only)
- Tokens: USDC only (mint: `EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v`)
- SDK: `@solana/web3.js` + `@solana/spl-token`
- RPC: `https://api.mainnet-beta.solana.com` (free public) with fallback to Helius free tier (API key stored in env)

## GASLESS FLOW FOR SOLANA (implement exactly this)

1. User builds an SPL token transfer transaction (USDC), partially signs it with their private key
2. Client sends the partially-signed transaction to the server endpoint `/api/solana/relay`
3. Server sets the sponsor wallet as `feePayer`, checks if recipient has an ATA for USDC mint — if not, prepends an `createAssociatedTokenAccountInstruction` (sponsor pays the ~0.002 SOL rent)
4. Server signs with sponsor wallet (feePayer signature only) and broadcasts via `connection.sendRawTransaction`
5. Server returns `{ signature, explorerUrl }` to client
6. Track ATA creation cost per user in DB (or a simple log) so you can monitor sponsor spend
